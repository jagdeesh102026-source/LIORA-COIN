# OXENIQ — Open Decisions Log

This document catalogues critical technical, tokenomic, architectural, and regulatory decisions requiring formal approval from the project owner before enabling live purchases or deploying mainnet liquidity.

> **CRITICAL ARCHITECTURAL DIRECTIVE**:  
> In accordance with project instructions, safe placeholders and configurable interfaces are implemented in code. No unconfirmed assumptions or guessed answers are hardcoded into production contracts. Live e-commerce purchases and liquidity operations remain disabled until these items are approved.

## Change Management Process
When a decision is approved by management:
1. Record the approval date, authorizing manager, and reference documentation.
2. Update the status in this table to `APPROVED`.
3. Apply the approved parameter to configuration files and deployment scripts.
4. Run integration tests to verify the approved behavior.
